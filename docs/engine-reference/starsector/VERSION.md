## Compile classpath (from `starsector-core`)

`starfarer.api.jar`, `json.jar`, `log4j-1.2.9.jar`, `lwjgl.jar`, `lwjgl_util.jar`

## What is official and what is not

- **Official API**: `com.fs.starfarer.api.*` in `starfarer.api.jar`. Prefer it always.
- **Unofficial**: the obfuscated core UI classes (`com.fs.starfarer.ui.*`,
  `com.fs.starfarer.combat.CombatState`). The mod reaches them through compile-time stubs in
  `stubs/` (generated by `tools/gen_stubs.py`). They can change in any game patch without
  notice; a game update means re-checking every stub.
- One option-data method is literally named `new`; `tools/rename_new.py` patches the call in
  `DialogBridge.class` after compiling.

## Class loader limits

The game's script class loader refuses reflection (`java.lang.reflect`) and `java.io.File`
access. `tools/build.sh` fails the build if either shows up in the classes. File I/O goes
through `Global.getSettings()` (`readTextFileFromCommon` / `writeTextFileToCommon`), which
works only under `saves/common/` and adds `.data` on disk.

## Knowledge gap warning

Starsector's API is thinly documented and changes between releases. Before using an API
call that is not already used in `src/`, check the javadoc in `starfarer.api.zip` (ships
with the game) or the existing code. Do not guess signatures.
