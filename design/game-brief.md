**One-sentence pitch:** A mod for Starsector 0.98a that lets Claude play the player's
single-player campaign on their behalf, inside safety rules the mod enforces in code.

## Core loop
- Claude reads `state.txt` / `events.txt`, then writes a command batch to `inbox.txt` (citing `#since <event>`).
- The mod runs the batch as goals (travel, dock, resupply, repair, hunt bounties, trade trips, explore), answering routine dialogs by editable rules.
- The governor lets game time pass only inside a granted `run` budget and pauses on alarms; the player approves spending in in-game popups.
- Results go back to the event log and state file, and Claude plans the next batch.

## Player goal & fail state (for the Starsector player using the mod)
- Working: Claude plays the campaign safely on the player's behalf and makes progress (confirmed by the author).
- Fail: the mod lets Claude break a locked rule or lose the fleet, or Starsector freezes. INTENT UNKNOWN — failure cases inferred from the 1.0.9 fixes (`SUMMARY.md`), not confirmed. A measurable "progress" threshold (credits, bounties, exploration) is also unspecified.

## MVP — what must exist for the mod to do its job
- Command pipeline: inbox batches, instant commands and goals, event log, state file.
- Governor: run budget, alarms, the player's pause is never undone.
- Locked safety rules: keep list, price ceilings, fuel and supply gates, `control player` refused, no cheats, in-game approval popups for spending.
- Bounty hunting and trade trips, with a read-only `preflight` GO/NO-GO.
- Events/state output, the single in-game panel, and editable dialog rules.

## Out of scope — not building this
- The agent never clicks the approval popup (screen control or any other route); a "yes" in chat is not approval.
- Colony founding and survey automation (the survey screen can't be driven yet; `explore_survey = false`).
- No changes to the player's game install (jar copy, `vmparams`) without the player's explicit OK.

## Build order
1. Command pipeline + governor (time only passes inside a budget).
2. Locked safety rules and approval popups.
3. Goals: travel, dock, resupply, repair, hire, explore.
4. Bounty hunting and trade trips, with preflight.
5. Panel, dialog rules, state/event polish.
